**加权成本（输入 1×、缓存读 0.1×、输出 1.5×）：B 反而贵 24%。**

### 失败原因

1. **自包含提示词太贵**：3 个提示词文件共约 430 行，而交付物才 700 行
2. **提示词会永久留在上下文**：每写一个提示词，之后每一步都要重读它
3. 缓存读取涨了 58%，把省下的输出 token 全吃了

### 质量差异

- 网页版有 1 个测试失败：`store.path == os.path.join(...)` 在 Windows 上因 `expanduser` 保留 `/` 而失败
- 漏了规格里的 `README.md`（需补写）
- `stats` 少了两个小标题、id 列左对齐（观感差异）

功能、退出码、CLI 冒烟输出与 A 组一致。

## 关键结论

### 1. 省 token 的机制不是"输出少"，而是"步数少"

每多一步，整个上下文（含缓存）就要重读一遍。

| 做法 | 步数 | 每步额外负担 |
|---|---|---|
| 自己写 | 15 | — |
| 派活 v1（提示词进上下文） | 16 | 4300 token × 剩余步数 |
| **派活 v2（规格在磁盘）** | **5** | **0** |

### 2. 什么规模才值得派活

| 产出规模 | 结论 |
|---|---|
| < 500 行 | ❌ 自己写 |
| 500~1500 行 | ⚠️ 收益不明显（v1 的教训） |
| **> 2000 行 / > 5 文件** | ✅ **派活** |
| 批量同构（20 个相似文件） | ✅✅ 强烈推荐 |

### 3. 必须能自动验收

如果派活后还得读全文检查，等于把产物拉进上下文，省的 token 全还回去了。

**正确做法**：`--pytest` 让脚本跑测试，只回一行摘要。

### 4. 时间成本是硬代价

墙钟从 52 秒涨到 250 秒（4.8 倍）。紧急任务别派活。

## 复现方法

```bash
# 1. 启动桥接
scripts\start_bridge.bat

# 2. 准备规格文件（参考 docs/HOW_IT_WORKS.md 的项目结构）

# 3. 写任务列表 tasks.txt（每行一个任务）
#    实现 models.py 和 test_models.py
#    实现 store.py 和 test_store.py
#    ...

# 4. 派活
python skill/ask_web.py --spec spec.md --task-file tasks.txt --out-dir out --pytest

# 5. 记录你（调用方）的 token 消耗
#    DSH 用户：python C:\fw\tokstat.py --delta
```
